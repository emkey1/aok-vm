- **The gadget translator in tctiSH's QEMU (tctiSH/qemu#2): their architecture asks, queued 2026-10-20.** iamrecursion (the maintainer) read the core and the x86-64 front end and is interested in the speed, not in the maintenance burden as it stands. Only x86-64 matters to tctiSH; the other front ends wait until it is maintainable. They offered to write a high-level design and roadmap, and we said yes: **wait for it before starting**, and build to it. Their name for it may be "Rich Code Interpreter (RCI)". The user may not keep at this long term and is glad for the maintainer to take the approach on (it is all GPL-2.0-or-later, and they were told so). Their asks, as they put them:
  1. **Decode from TCG's tables.** Split `disas_insn` before its first TCG op into an `x86_decode_insn()` that returns ok, illegal, unknown or #GP. TCG carries on as now, and the gadget translator looks its gadget up by `decode.e.gen`, the operand units and sizes, and whether there is a memory operand, and stops the TB where there is none. Unknown: whether that first half is free of side effects.
  2. **Generate the gadgets.** A Python generator, like TCTI's `tcti-gadget-gen.py`, producing from one table (op x form x width x single- or multi-threaded): the gadgets as naked C with extended asm, the translator's selection table, and the lazy-flag facts per op. This replaces the assembler macros.
  3. **Constants from QEMU's headers.** The TLB probe and `aok_lookup_jc` take their offsets from QEMU's own types as `"i"` asm operands (`TCTI_TLB_FAST_OFS(mmu_idx)` and the like), with `QEMU_BUILD_BUG_ON` for each layout assumption (table after mask in `CPUTLBDescFast`, flags and cflags loaded as a pair) and a test of the gadget's jump-cache hash against `tb_jmp_cache_hash_func` over a spread of pcs. Ours hard-code `TLB_FOLD 8`, which their 8c4e4b8d4a removed: after a rebase every probe would miss silently and take the slow path.
  4. **Hybrid mode.** Off entirely when the hybrid runs the JIT. TBs flush as any other (they do).
  5. **Feature parity.** Every mode the hybrid swaps between offers exactly TCG's features, so no AVX-512. FP results must not change at a swap either, and our x87 and SSE gadgets give the hardware's answers where TCG's softfloat differs. The reduced setting (`QEMU_AOK_X86_NOX87=1 QEMU_AOK_X86_NOVEC=1 QEMU_AOK_X86_SSEHELPERS=1`) matched the full set on non-AVX code back to back, so the likely shape is general-purpose registers only, floating point left to QEMU.
  6. **No guest announcement** (the device-tree `aok,engine` and the CPUID brand).
  7. If vector gadgets stay: VEX `vpextrq`, `vpextrd` and `vextractps` (VEX.128.66.0F3A 16/17) caused Blender's 73.6 million hand-offs, the one workload where the gadgets sit well behind the JIT.
  Done: the cmp_vec fix (their #4, merged), the TB race fix (their #5, waiting for review), and their numbers (posted on #2: the bench kit is in qemu-aok-plugin's memory note; MBP5 ~/tctish-bench).

- **The pair-fusing pass exists twice: `jit_pair_fuse` (jit/gen.c) and `aok_gen_pair` in the QEMU plug-in (qemu-aok, accel/tcg/aok.c).** The gadget sources are shared (506bf387d the ALU family, 7db3de6cd loads, stores and branches; aok/docs/engine-study.md, section 10); the pass that picks the fused gadget was ported by hand on 2026-10-12 because jit/gen.c had other sessions' uncommitted work in it. Proposed: move the table lookup and the stream rewrite (replace the first gadget's word, drop the second's, pick the forwarding variant when the second's operand names the register the first wrote) into a small C file with no AOK types in its interface, which both trees compile, and have `tools/check-shared-gadgets.sh` build it standalone.
- **The QEMU plug-in's translator does not fold the idioms AOK's does, so the pairs that name them never occur there.** gen.c folds a shift pair (`sll_srl`, `sll_sra`: gen_riscv64_try_after_slli), a shift and an add (`sll_add`), a constant or bit test and its branch (`b<cond>_ri/_ir`, `andi_beqz/bnez`: gen_riscv64_try_li_branch, _try_andi_branch) and an add with the load through it (`add_l*`, memory.S, not a shared body yet) before the pair pass runs. The plug-in assembles all of those gadgets (shared sources) and selects none: qemu-aok target/riscv/tcg/aok/translate.c decodes one instruction a step and has no look-ahead. Needed there: a peek at the next instruction in the same page (and `n_insns + 2 <= max_insns`), the 16-bit forms of the second instruction expanded (c.srli, c.srai, c.add, c.beqz, c.bnez), two `aok_gen_insn_end` calls for a folded step. `sll_add` and the branch idioms are in several of the most frequent pairs (`sll_add+lhu`, `and_rr+sll_add`, `sll_add+ld`). Also not taken: pairs that begin with `auipc`, which is the plug-in's own `pcrel` gadget because QEMU's blocks are position independent, where AOK's is `mov_const`.
